# LeetCode Hot 100 本地练习

100 道题，支持 Python、JavaScript、C++，提供核心代码与 ACM 两种模式。测试用例负责判断输出是否正确；AI 助手用于解释错误、分析复杂度和评审代码。

知识讲解按具体问题组织：先讲思路怎样推出来，再说明适用条件、容易写错的地方和练习顺序。13 篇文章各有三种语言的可编辑运行示例。

## 启动

推荐安装 **Node.js 18 或更高版本**，不需要安装项目依赖或打包。

| 系统 | 启动方式 |
| --- | --- |
| macOS | 双击 `一键启动(MACOS).command` |
| Windows | 双击 `一键启动（WIN）.bat` |
| 终端 | `npm start` 或 `bash start.sh` |

程序会在 8931–8951 中寻找空闲端口，然后打开浏览器。只监听本机的 `127.0.0.1`。按 Ctrl+C 停止。

只有 Python 3 时，启动脚本仍可使用原来的静态模式，但进度只能存在浏览器里，OpenCode Go 本地转发不可用。Windows 的 Python 回退使用固定端口 8931。

不要直接双击 `index.html`；编辑器和判题需要通过本地网页服务器加载。

## 进度直接保存在仓库里

使用 Node.js 启动后，右侧「进度」侧栏显示保存状态，默认收起，点击后可查看详情与导出备份。练习过程中的这些内容会自动保存到 `progress/learning.json`：

- 各题的尝试记录、通过情况和复习安排；
- 各语言、各模式的代码草稿和自定义输入；
- 错题原因与笔记；
- 知识文章阅读状态、示例草稿与预测输出；
- 语言、主题等界面偏好。

修改后约一至两秒写入，也可以点“立即保存”。结束练习前确认顶部显示已保存，再关闭页面或提交文件。浏览器仍保留一份副本，文件保存失败时会提示，不能把“浏览器里有”当成“文件已保存”。

首次打开时，若当前浏览器、当前端口下已有进度而文件不存在，会把已有进度写入文件。旧版进度若在另一浏览器或端口，请先在旧页面导出备份，再到新页面的题库首页导入。若两边都有不同数据，页面会让你先导出浏览器备份，再选择使用文件或浏览器中的进度。这里的选择会替换目标数据，不会猜测如何合并同一道题的不同草稿。

文件每次保存都会检查版本，再通过临时文件替换。另一个页面或 Git 已经改过文件时，当前页面会停止覆盖，提示先备份再刷新处理。文件损坏也不会被自动清空。

API Key 和 AI 对话不进入进度文件。不要把服务商密钥写进学习笔记或代码草稿。

## 使用自己的 fork

先在 GitHub fork 原仓库，再克隆自己的 fork。当前工作副本已经设置为：

- `origin`：`https://github.com/hrz6976/leetcode-hot100.git`
- `upstream`：`https://github.com/kernelvale/leetcode-hot100.git`

本次重构位于 `codex/learning-refactor` 分支。换电脑时可以直接克隆这个分支：

```bash
git clone --branch codex/learning-refactor https://github.com/hrz6976/leetcode-hot100.git
cd leetcode-hot100
npm start
```

当天练习结束后：

```bash
git add progress/learning.json
git commit -m "记录今天的刷题进度"
git push -u origin HEAD
```

换电脑时，克隆你自己的仓库并启动，页面会读取进度文件。若已有本地副本，先保存并提交本机进度，再拉取更新，最后刷新页面。不要在两台电脑上同时修改同一份进度后直接覆盖；需要保留两份备份并处理冲突。

公开 fork 中提交的代码与笔记也会公开。进度文件说明见 [progress/README.md](progress/README.md)。浏览器备份导入、导出仍然可用，可用于从旧版本迁移。

## OpenCode Go 订阅

本机 OpenCode 已连接 Go 订阅时，项目会自动复用其 API 凭据。密钥由本地服务读取，不传回浏览器、不复制进仓库。打开 AI 助手即可提问，默认使用 `kimi-k2.6`。

若本机没有配置 OpenCode，或你希望使用另一把 Key：

1. 用 Node.js 启动项目。
2. 打开右侧“AI 助手”，进入设置，选择“OpenCode Go 订阅”。
3. 填入 OpenCode 控制台的 Go API Key。默认模型为 `kimi-k2.6`，也可以填写 Go 支持的其他 Chat Completions 模型 ID。
4. 保存配置后提问；题目和当前草稿可以按需附带。

判题后点击“请 AI 评审这次提交”，助手会准备问题，并绑定当次提交的代码与测试结果。点击“发送”后才调用模型。

Go 请求通过本地同源服务转发到 `https://opencode.ai/zen/go/v1/chat/completions`。转发使用项目自身的客户端标识，并为每段对话发送稳定的 `x-opencode-session`；清空对话后生成新编号。手动填写的 API Key 保存在当前浏览器，本机 OpenCode 凭据仍留在原配置文件，不写入仓库；从进度文件恢复数据时也不会清除已有 Key。

当前接入的是 **Chat Completions 协议**。官方为部分模型提供 Messages 或 Responses 协议，这些模型不能直接填入此适配器。模型列表、使用范围和订阅限制以 [OpenCode Go 官方文档](https://opencode.ai/docs/go/)为准。Go 面向编程代理类请求，本项目将它用于算法代码讲解与评审；是否接受具体请求以及可用额度由服务商决定。

AI 的评语不修改题目的测试通过状态。代码通过已有测试，也不代表 AI 或测试已经证明它对所有输入都正确。

仍可使用 Kimi、DeepSeek、OpenAI 和自定义 OpenAI 兼容接口。旧 Kimi Coding 接口继续通过 8966 端口的本地代理转发；Go 使用当前网页端口，无需手动启动额外代理。

## 离线与联网

JavaScript 判题在浏览器本地执行。Python 使用 Pyodide；代码编辑器使用 Monaco。存在完整的 `vendor/` 资源时，两者可以离线加载；资源不可用时会尝试 CDN，编辑器最终还可降级成文本框。

C++ 仍由现有远程编译服务执行，需要联网，提交代码会发送至该服务。AI 助手也需要联网，发送时会把勾选的题目、代码与对话内容交给所选服务商。

## 开发校验

```bash
npm test
```

包括索引一致性、存储与判题单元测试、本地服务读写及冲突测试、Go 转发测试、39 个知识示例，以及 100 题六套参考答案校验。

校验 Python 代码需要 `python3`，校验 C++ 需要 `g++`。没有 C++ 编译器时，相应检查会明确跳过；不能把跳过当成验证通过。Go 转发测试使用模拟服务，不消耗订阅额度；真实账号连通性可以使用本机 OpenCode 的 Go 凭据或手动填写的有效 Key 检查。
